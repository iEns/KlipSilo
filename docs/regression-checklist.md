# KlipSilo manual regression checklist (core features)

- **Build under test:** v1.2.0-beta.x (current beta.6 = `3e2513e`). **Baseline:** v1.1.0 (`2a5e8eb`).
- **Source:** `../FEATURES.md` with Jens's corrections from 2026-10-18:
  - Conversion *to* DOCX never existed and is dropped. DOCX → PDF is a v1.1.0 feature and stays in scope (Silas, 2026-10-18).
  - The duplicate-share dialog (R2) and undo/redo replacing "Clear all" (R3) are intended.
  - Share intake works.
  - Tap opens or views a clip. That is intended.
- **Scope:** core functions only. There are no text-overflow, layout or polish checks.
- **Item IDs:** each item has a stable ID (section letter + number, e.g. C3) that `../FEATURES.md` links to. Keep IDs stable; add new items at the end of a section.
- **Every item passes only if:** nothing crashes, and you return to the list without losing data.
- **Sample files to keep at hand:**
  - a JPG
  - a text PDF
  - testaroo `job-application.pdf` and `event-registration.pdf`
  - a DOCX, an XLSX, an RTF, a TXT, an HTML file, an APK or ZIP
  - a PDF form with a password field
  - a link to a PDF or image file, and a link to an ordinary web page
  - a web link
  - a short text

## A. Capture and share intake
- <a id="A1"></a>**A1 · Save clipboard:** with an empty clipboard and an empty library, open KlipSilo. → The **Save current clipboard** button is hidden and the empty state leads the list. Now copy a text in any app, return to KlipSilo, and tap **Save current clipboard**. → The button appears and a new text clip appears at the top with that text. Empty the clipboard again while clips remain: the button stays in place but is disabled with "Clipboard is empty" under it (#120). A failed save names the reason (empty, nothing saveable, too large) and offers **Retry** when the clipboard still has content; the clipboard is kept.
- <a id="A2"></a>**A2 · New text clip:** tap **+**, type a text, then go back. → The clip is saved. Leaving it empty or discarding it saves nothing.
- <a id="A3"></a>**A3 · Share text and links in:** share a sentence from Notes, then share a URL from Chrome, each to KlipSilo. → You get one Text clip and one URL clip with the right content.
- <a id="A4"></a>**A4 · Share an image and a PDF in:** share the JPG and the PDF from Files. → You get an Image clip (type and size shown) and a PDF clip.
- <a id="A5"></a>**A5 · Share any other file in:** share a DOCX, TXT and APK/ZIP from Files. → Each one appears as a File clip with the right name, type and size.
- <a id="A6"></a>**A6 · Duplicate share:** share the same JPG again. → The "Already saved" dialog appears. Cancel saves nothing, Save again adds a copy, and Open existing opens the original.
- <a id="A7"></a>**A7 · Share a file and text together:** from an app that shares a file with a caption (e.g. Photos or Files with text added), share both to KlipSilo in one go. Use a file that is not already a clip, so the A6 dialog does not appear. → Two clips appear: the file (Image, PDF or File clip) and a Text clip with the text. Neither is lost.
- <a id="A8"></a>**A8 · Download from URL:** on a URL clip that points to a PDF or image, sheet → **Download from URL**. → "Downloading…" then "File downloaded", and a new PDF or Image clip (or Text/File clip for other files) appears at the top. On a link to an ordinary web page you get "Could not download file" and no clip.

## B. Clip list
- <a id="B1"></a>**B1 · Search:** type part of a clip title or text. → Only matching clips are shown. When nothing matches, including on an empty library, the empty state names the query and offers **Clear** instead of saying **No clips saved yet**; clearing the search restores the full list.
- <a id="B2"></a>**B2 · Filter chips:** tap each chip in turn (Text, Markdown, URL, Image, PDF, File, Location, and Locked if present). → Text and Markdown are separate chips: a Plain Text clip appears only under Text, a Markdown clip only under Markdown. Only clips of that type are shown, and an empty result names that chip with a matching hint (even when the library itself is empty). **All** restores the list. When the row runs past the screen edge, a `<` cue appears at the start and a `>` cue at the end while the row can still be swiped that way (no fade); swiping sideways reaches the remaining chips and the cues disappear at each end (#123, #127).
- <a id="B3"></a>**B3 · Pin:** pin a clip from the row icon or the sheet → **Manage** → **Pin / unpin**. → It moves to the top and stays there after the app restarts. Unpinning reverses this.
- <a id="B4"></a>**B4 · Delete and undo:** delete one clip from the sheet (confirm) — sheet → **Manage** → **Delete** — and swipe another one away. Tap **Undo** on one of them. → The undone clip comes back. The other one stays gone after the app restarts. The undo snackbar sits above the **+** button.
- <a id="B5"></a>**B5 · Lock:** lock a clip from the sheet → **Manage** → **Lock/unlock**. → Delete, swipe and edit are blocked for it. Unlocking restores them.
- <a id="B6"></a>**B6 · Rename and Duplicate:** sheet → **Manage** → **Rename**, then **Manage** → **Duplicate**. → The new title shows. The duplicate is a separate clip with the same content.
- <a id="B7"></a>**B7 · Spilled text meta:** create a Plain Text clip and a Markdown clip with long bodies (over 256 KiB), then look at the list. → Both rows show the type name **Text** / **Markdown** with the size; neither shows a bare **TXT** or **MD** storage extension (#127).

## C. Opening and viewing clips (tap, or the action sheet)
- <a id="C1"></a>**C1 · Plain Text and Markdown clips:** tap each. → The editor opens with the full text, ready to read or edit. In the sheet, **Present** still opens the reader, where dark/bright theme and auto-scroll work; Markdown headings, lists, quotes and emphasis render formatted there, while Plain Text shows its characters literally. The Markdown insert (**MD**) toolbar appears only on Markdown clips (#127).
- <a id="C2"></a>**C2 · URL and location clips:** tap each. → The URL opens in the browser. The location opens in Maps.
- <a id="C3"></a>**C3 · Image clip:** tap it, and also try long-press → **View content**. → The image shows, with no crash (#66).
- <a id="C4"></a>**C4 · Non-text file clips:** tap the DOCX, the TXT and the APK/ZIP, and try **View content** on each. → DOCX and TXT show readable text. The APK/ZIP shows a file info card or message with its actions. Tap **More** on the file info card and use an action from the full sheet (e.g. Rename, Pin or Delete) without going back to the list (#71). None of them crash (#66).
- <a id="C5"></a>**C5 · Find links:** on a text or PDF clip that contains a URL and a phone number, open the sheet → **Convert & Edit** → **Find links**. → Both are listed. Tapping one opens the browser or the dialer.
- <a id="C6"></a>**C6 · Action sheet layout:** long-press a Plain Text clip and a Markdown clip (or tap ⋮). → **Edit**, **Present**, **Share as text**, **Share as file** and **Download as file** sit at the top; **Convert & Edit** is collapsed by default and expands to **Text → PDF** plus **Make this Markdown** (Plain Text) or **Make this Plain Text** (Markdown) — and on a PDF also Annotate, Fill form, Edit pages and Find links. **Manage** groups **Rename**, **Duplicate**, **Pin/Unpin**, **Lock/Unlock** and **Delete**. Text → TXT is gone. No action is missing, and no separate Tools section is shown. Running any action closes the sheet before it runs, so its toast/snackbar is visible and the next tap works immediately (#122, #127, #128, #129).
- <a id="C7"></a>**C7 · One-shot text-kind upgrade:** open a pre-upgrade install (or restore a backup made before this change) with Plain Text clips, FILE clips ending in `.txt`/`.md`, an HTML text clip and a DOCX. → On first open, Plain Text stays Plain Text (even when its body starts with `#`/`-`), the `.txt` file becomes Plain Text, the `.md` file becomes Markdown, the HTML text becomes an `.html` File clip that opens as a rendered read-only page, and the DOCX stays a File. Restarting the app does not migrate again (#127).

## D. Sharing out and export
- <a id="D1"></a>**D1 · Share out:** sheet → **Share as text** on a Plain Text and a Markdown clip, and **Share** on an image and a file clip. → The system share sheet carries the right text or file. For example, it pastes correctly into Gmail.
- <a id="D2"></a>**D2 · Save to Downloads:** run it on an image, a PDF and a file clip. → Each file appears in Downloads with its correct name and opens.
- <a id="D3"></a>**D3 · Backup and restore:** Tools → Maintenance → **Backup** to ZIP. Delete a test clip, then **Restore** from the ZIP. → The deleted clip comes back with its original id, and the other clips aren't duplicated or lost. Restore the same ZIP again → every clip that already exists is skipped (same backup id), so nothing is duplicated.
- <a id="D4"></a>**D4 · HTML file:** on an HTML file clip, tap it and then use sheet → **Open in browser**. → The viewer shows the rendered page read-only; **Open in browser** renders it in the browser. The clip is unchanged and there is no editor for it (#127).
- <a id="D5"></a>**D5 · Share/Download Plain Text and Markdown files:** sheet → **Share as file** on a Plain Text clip and a Markdown clip, then sheet → **Download as file** on both. → The share sheet receives a `.txt` / `.md` attachment with the clip's body; Downloads receives a named `.txt` / `.md` file that opens with the right content (#127).

## E. Conversions (each one creates a new clip)
All conversions below are under the sheet's **Convert & Edit** row — tap it to expand (collapsed by default).
- <a id="E1"></a>**E1 · Text → PDF:** use a Markdown clip (with a heading and a list) and a Plain Text clip whose body contains the same `#`/`-` characters, then sheet → **Convert & Edit** → **Text → PDF** on each. → The Markdown clip's PDF shows formatted text; the Plain Text PDF shows the literal characters. The sheet closes before the toast appears, and the next clip tap works immediately (#127, #128, #129).
- <a id="E2"></a>**E2 · Image → PDF:** run it on the JPG. → A new one-page PDF clip holds the image.
- <a id="E3"></a>**E3 · DOCX → PDF:** on the DOCX file clip, use the sheet (long-press or ⋮) → **Convert & Edit** → **Convert to PDF**. → A new PDF clip appears with the document's headings, text, lists, tables and images, and it opens in the PDF viewer. A Word `Title` style renders as a heading, List Bullet / List Number paragraphs keep their `•` / `1.` markers (including styles whose numbering lives on the style), and paragraphs after a table start below the table instead of overlapping its last row (#75).
- <a id="E4"></a>**E4 · PDF → Image and PDF → Text:** run both on the text PDF. → You get image clip(s) per page, and a text clip with the PDF's text.
- <a id="E5"></a>**E5 · PDF → HTML retired:** open a PDF clip's **Convert & Edit** menu. → There is no **PDF → HTML** row, and no action creates an editable HTML text clip (#127).
- <a id="E6"></a>**E6 · Try as text:** use the sheet's **Convert & Edit** → **Try as text** on an unknown file. → You get a text result or a clear message, with no crash.
- <a id="E7"></a>**E7 · XLSX, RTF and TXT → PDF:** on each file clip, sheet → **Convert & Edit** → **Convert to PDF**. → Each gives a new PDF clip with the content (XLSX: sheets as tables; RTF: formatted text; TXT: plain text) that opens in the PDF viewer.
- <a id="E8"></a>**E8 · Make this Markdown / Make this Plain Text:** on a Plain Text clip, sheet → **Convert & Edit** → **Make this Markdown**; then on the result choose **Make this Plain Text** (also try the top-bar toggle in the editor with unsaved edits). → The same clip changes kind in place, its body is kept, the Markdown insert toolbar appears/disappears, and a spilled body moves between `clip.txt` and `clip.md`. Text → TXT is no longer offered (#127).
- <a id="E9"></a>**E9 · HTML file → PDF:** on a File clip ending in `.html`/`.htm`, sheet → **Convert & Edit** → **HTML → PDF**. → A new PDF clip shows the rendered page (headings, paragraphs, lists), not the raw tags. HTML files are preview-only; Plain Text/Markdown clips don't offer this row (#127).
- <a id="E10"></a>**E10 · PDF output settings:** Settings → **PDF & export**, directly under the Display mode controls (the row shows the current font, is collapsed by default, and expands on tap): change Font type, Font size, Line spacing, the two margins and Max output resolution, then repeat E1. → The font buttons read **System**, **Sans Serif**, **Serif** and **Mono** (no "(≈Arial)" suffixes) and each is drawn in the family it selects; the new PDF uses the new font, size, spacing and margins. Plain text → PDF embeds the chosen font (Sans, Serif or Mono), so the three are visibly different. The settings survive an app restart.

## F. PDF viewer and PDF tools
- <a id="F1"></a>**F1 · PDF viewer:** tap a multi-page PDF, swipe horizontally through pages, pinch-zoom, pan while zoomed, and use go-to-page. → The pages render. While the page is not zoomed, a horizontal swipe flips to the next or previous page; once zoomed, pinch and one-finger pan move the page and do not flip it. The page buttons and go-to-page still work.
- <a id="F2"></a>**F2 · Viewer actions:** in the viewer, run OCR page, Save page as PDF, Read QR (on a page with a QR code) and Extract images. → Each one gives a correct new clip or result. The bar's labels stay on one line (no mid-word wrap), including Japanese **OCR** / **保存** (shortened bar strings) and other long locales: they shrink to fit, then become icon-only or move into the overflow menu (#86).
- <a id="F3"></a>**F3 · Combine:** Tools → **Combine** two PDFs and an image, and **Combine texts** with two text clips. → You get one merged PDF clip in the chosen order, and one merged text clip. Combine texts accepts Plain Text and Markdown clips: a mixed Plain + Markdown selection produces a Markdown clip, while all Plain stays Plain Text (#127). With fewer than two image/PDF clips, **Combine PDFs** shows a hint that two are needed instead of opening an empty picker (#131). With fewer than two text clips, **Combine texts** shows a hint and **Create another** instead of opening an empty picker.
- <a id="F4"></a>**F4 · Edit pages:** PDF sheet → **Edit pages**, reorder two pages, delete one, and save. → The new PDF has the expected page order and count.
- <a id="F5"></a>**F5 · Zoomed pan stays in view:** open a PDF in View Content and in Mark up; pinch in slightly past fit-to-screen, then try to pan the page fully off in several directions. → Some of the page always remains on screen and it can be panned back; fit-to-screen (scale reset) still centers the page (#148).
- <a id="F6"></a>**F6 · Preview ends above the viewer bar:** open a PDF from the clips list with View Content (not Mark up), zoom in, and pan to the bottom of the page. → The page viewport ends above the Save page / OCR page / ⋮ bar, so the bottom of the page is not hidden under it and can be panned fully into view; the page controls, Save, OCR and ⋮ stay usable (#160). Pinch in and out repeatedly while the fingers are down: the zoom stays smooth and continuous with no violent jitter or flicker between two zoom levels, and lifting the fingers leaves one stable scale (#160 reopen). Mark up still ends above its tool selector (#152) and the F5 pan clamp still holds.

## G. Fill PDF form (testaroo job-application and event-registration)
- <a id="G1"></a>**G1 · Single-line fields:** fill Full name and Email, then **Save PDF**. → The values show in the preview. The saved PDF clip shows them in Files or another PDF viewer.
- <a id="G2"></a>**G2 · Multi-line field:** type several lines in **Cover letter** (job form) and **Notes** (event form). → There's no crash on the first character, the text wraps in the preview, and it's saved (#68).
- <a id="G3"></a>**G3 · Checkboxes and radio groups:** tick checkboxes. In each radio group (**Work authorization** on the job form, **T-shirt size** on the event form), check the heading and pick an option, then switch to another. → Each radio option shows the text printed on the form ("Citizen / Permanent resident", "Visa holder", "Needs sponsorship"; "S", "M", "L", "XL"), not the internal export value, and only one per group is selected. This is not shown as a single checkbox (#67). The group heading is the printed group name, never the first option; a group without a name has no heading (#72, #78). The choice is kept in the saved PDF.
- <a id="G4"></a>**G4 · Password field:** in a form with a password field, type a value. Use the eye button (**Show password** / **Hide password**). → The field shows dots by default and the value on Show. The note "This will be saved in the PDF as readable text." is shown. The preview shows dots (with a "Saved as readable text" pill when the field is large enough). The saved PDF holds the real value.

## H. Mark up PDF
- <a id="H1"></a>**H1 · Annotate:** on page 1, add a text box (two lines; press Enter for the second line), a line, a freehand stroke and a highlight. Move one item, then delete it via Select. Try Undo/Redo. Go to page 2 and add a stroke. → While typing, the field wraps at the same width as the text on the saved page and the draft is not also drawn into the page as a clipped single line; Enter adds a line (it does not save), and tapping outside or **Save** commits the box. All the tools work, and undo/redo steps back and forth correctly (#138).
- <a id="H2"></a>**H2 · Save:** tap **Save**. → A new PDF clip has all the annotations on the right pages, line breaks included. Saving with no changes creates no duplicate.
- <a id="H3"></a>**H3 · Colours and sizes remembered per tool:** in Mark up, tap the colour circle to open the palette and pick a non-default colour for text, then a different one for Line, a third for Draw and yellow for Highlight. Switch between the tools, change text and stroke size, then leave. Open Mark up again, also after an app restart. → The button shows the active tool's current colour, the selected swatch has a check, and each of text, line, draw and highlight keeps its own colour: picking a colour for one tool never changes another, and switching back restores that tool's colour. Yellow remains available for highlight strokes, and the last colours and sizes are preselected (#90, #144).
- <a id="H4"></a>**H4 · Leave with unsaved marks:** add a text box and a stroke, then press system Back and, separately, the top-bar Back. → Each time a Save / Discard / Cancel dialog appears. Cancel keeps editing, Discard drops the marks, Save creates the annotated PDF clip.
- <a id="H5"></a>**H5 · Unsaved marks survive a language change:** add a text box and a stroke, then change the app language (or recreate the activity, e.g. rotate) with Mark up still open and return to it. → The unsaved marks are still there, and Back still asks Save / Discard / Cancel.
- <a id="H6"></a>**H6 · Start from a blank PDF:** Tools → Create → **Blank PDF**. → A one-page white A4 PDF clip is created and Mark up opens on it; add a text box and a stroke, Save, and the new annotated PDF clip has one page (#121).
- <a id="H7"></a>**H7 · Insert, move and resize an image:** in Mark up, tap **Image** and insert one image from each source in turn: a saved image clip (**Clips**), **Gallery**, **Camera**, and **Files**. → Each placed image appears centred at about 40% of the page width. With **Select**, drag the image to move it, drag a corner to resize (width and height scale together, the ratio is kept), then delete one with the trash/✕ control and Undo/Redo it. Save. → The saved PDF shows the images at their placed positions and sizes on the right pages, also after reopening the clip; no rotate or crop is offered (#92).
- <a id="H8"></a>**H8 · Page edges when zoomed out:** open a white or blank PDF in Mark up (e.g. Tools → Create → **Blank PDF**) and zoom out until the page is smaller than the screen, then pan and zoom back in. → The page edges are clearly visible against the canvas: a soft non-white gradient behind the page, a thin frame around it and a light shadow under it, all staying glued to the page while zooming and panning. Check in light theme and, if Mark Up follows the theme, in dark theme too; keep it subtle (#146).
- <a id="H9"></a>**H9 · Text tool with the keyboard up:** in Mark up, tap **Text** and then tap the page so the soft keyboard opens. Tap in the **top ~1/4**, the middle and, separately, near the bottom, and type a few lines. → The page is fitted to the canvas **width** (not shrunk to the shorter canvas above the keyboard) and is panned so the whole text field stays readable above the keyboard. The page stays framed without grey letterbox bands that hide page content, and the text field always lands on the page content, not in grey (#161 reopen). With the keyboard still open after a **top** tap, pan the page as far as it will go in each direction. Toward the top, the **top edge of the page** meets the top of the canvas (the page is not stuck with its top clipped under the history bar). Toward the bottom, the **bottom edge of the page** meets the bottom of the canvas — there is no large empty grey band below the page (#161 Beta 10). Typing is readable without manually zooming. Dismiss the keyboard (system Back) and, separately, leave the Text tool. → The page returns to the normal fit-page view with the zoom/pan you had before the keyboard opened: no blank page and no stuck oversized zoom, and the text stays at the tapped page position. Check #152 (canvas above the tool selector), #153 (text-field width and caret padding) and #148 (no blank page after pinch) still hold (#161).

## I. Scan and capture
- <a id="I1"></a>**I1 · QR scanner and camera OCR:** Tools → QR on a QR code, and Tools → OCR camera on printed text. → The decoded text or link is offered or saved as a clip, and the OCR text is saved as a clip. Rotate to landscape in both screens: the title and hint header hide so the preview uses the full height, and the back arrow stays visible (#124).
- <a id="I2"></a>**I2 · OCR from an image clip:** sheet → **Convert & Edit** → **Crop/OCR from image** on a photo of text. → A text clip holds the recognised text. The crop frame includes everything it visually encloses: a full line at the right or bottom edge keeps its trailing characters in the OCR result (#82).
- <a id="I3"></a>**I3 · Location:** Tools → Location (current location; there is no typed-address entry). → A "Getting location" dialog appears; **Cancel** closes it without saving, and the back gesture or a tap outside does the same. Let it finish: a location clip is created with the address. The snackbar's **Open** opens the clip in KlipSilo, and tapping the clip opens Maps.
- <a id="I4"></a>**I4 · QR from an image clip:** open an image clip that contains a QR code and tap the **Scan QR** button. → The decoded message is shown with **Copy**, **Save to clip** and **Cancel**. Save to clip creates a text or URL clip. An image without a QR shows "No QR code found".

## J. Text editor
- <a id="J1"></a>**J1 · Edit and save prompt:** tap a Plain Text or Markdown clip to open the editor, change the text, and leave. → A "Save changes?" prompt appears (intended since beta.4, #27). Save, then reopen. → The change was kept. The top bar shows **Save** as a label when there is room (or the ✓ with a "Save" tooltip when collapsed); tapping it saves without the prompt. Share from the editor works. On Markdown the **MD** insert toolbar is present; on Plain Text it is hidden (#127). The **Preview** eye opens a full-screen overlay with the rendered pages and an X; Markdown renders formatted, Plain Text renders literally, tapping the preview does not open a page picker, and X returns to the editor (#127, #130).
- <a id="J2"></a>**J2 · Select word / sentence / paragraph:** in the editor, place the cursor in a word and use the **Select word / sentence / paragraph** button → **Word**, then **Sentence**, then **Select paragraph**. → Each selects exactly that unit around the cursor.
- <a id="J3"></a>**J3 · HTML is not editable:** open an HTML File clip (created by the one-shot upgrade or shared as a file). → The viewer shows the rendered page read-only; there is no HTML source editor and no Preview eye for HTML. Use **Open in browser** or **HTML → PDF** from the action sheet instead (#127).

## K. Settings and maintenance
- <a id="K1"></a>**K1 · Theme and language:** switch Light/Dark/System. → Each Display mode label is centered in its button. Switch the language to Danish, then German, then back to English or System default. → Each takes effect at once and survives an app restart. The App Info language stays in sync.
- <a id="K2"></a>**K2 · Bulk delete and unlock:** Tools → Maintenance → **Delete**, choose All or one type, then **Delete**. Then tap **Locked clips**, confirm **Unlock all**. → Only that type is removed, and locked clips are kept. Unlock all asks for confirmation first: **Cancel** (or tapping outside) keeps every lock, and **Unlock** clears every lock.
- <a id="K3"></a>**K3 · About and Privacy:** in Settings, open **About** and **Privacy policy** in turn; they sit below the collapsed **PDF & export** row (the Guide section — Tips / Limitations / Why / Use cases — was removed in #159). → Each opens with its content, scrolls, and back returns to Settings. **Privacy policy** shows the text for the current app language (all 13 picker languages; unknown tags fall back to English), with the Google Play paid-download wording and effective date 25 October 2026 (#87).
- <a id="K4"></a>**K4 · Offline only:** turn on airplane mode and restart the app. Run A1, A2, C1, E1, E3, F1, F2, G1, H2 and I2. → Everything works with no network and no sign-in prompt. Only Download from URL and opening a link in the browser need the network, and they fail with a message, not a crash.
- <a id="K5"></a>**K5 · Rate on Google Play:** in Settings → About, below **Privacy policy**, tap **Rate KlipSilo on Google Play**. → The Play Store opens on the production listing (`com.phaprodevelop.klipsilo`), including from a `.beta` build. With no Play Store app (or if it cannot open) the web listing opens in a browser instead. There is no in-app review prompt, dialog or "remind me later" anywhere (#163).
